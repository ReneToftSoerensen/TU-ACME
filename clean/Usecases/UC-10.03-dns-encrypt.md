# UC-10.03: DNS Plugin Credential Encryption

## Narrative

As a **security-conscious operator**, I want to **store DNS plugin credentials encrypted**, so that **sensitive authentication tokens are not readable in plaintext**.

## Acceptance Criteria

- [ ] DNS plugin credentials prompt uses `Read-Host -AsSecureString` (or similar)
- [ ] Credentials are converted to DPAPI-encrypted strings via `ConvertFrom-SecureString` (no key)
- [ ] Encrypted credentials are stored in `config.json`
- [ ] On config load, encrypted credentials are decrypted via `ConvertTo-SecureString`
- [ ] Decrypted credentials are passed to Posh-ACME for DNS validation
- [ ] Credentials are never logged to Event Log
- [ ] DPAPI encryption is per-machine

## Implementation Notes

- DNS credentials stored in config.json as encrypted strings
- Plugin name and decrypted creds passed to Posh-ACME's plugin system
- Consider storing plugin name separately (not encrypted)

## Test Coverage

**Unit:** Mock `ConvertFrom-SecureString` and `ConvertTo-SecureString`; verify encrypt/decrypt flow.

**Integration:** Configure DNS plugin, verify creds are encrypted in config file.

**Scripts:** Renewal script uses decrypted creds for DNS validation.
