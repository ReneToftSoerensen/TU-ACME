PoshTUI — Data Flow Diagram
PoshAcmeTui.ps1 · PoshAcme-Renew.ps1 · PowerShell 7 / Windows
1 Entry Points / Triggers who kicks off the work
Administrator interactive
Launches pwsh -File PoshAcmeTui.ps1 from an elevated PowerShell 7 console. Selects a menu option (N / R / A / M / B / S / T / D / W / Q).
Windows Task Scheduler scheduled
Fires registered PoshTUI-* task (default: weekly Monday 09:00) running as SYSTEM with highest privileges.
↓
2 Script Layer two thin entry-point scripts
PoshAcmeTui.ps1 interactive
Loads ~/.poshtui/config.json → Show-MainMenu loop → dispatches to Invoke-CreateCertificate, Invoke-RenewSingle, Invoke-RenewAll, Invoke-ManageRenewals, Invoke-BrowseIISBindings, Invoke-SelectAccount, or Invoke-ManageScheduledTasks.
PoshAcme-Renew.ps1 scheduled
Accepts -ServerName / -AccountID / -LogPath. No TUI, no menu. Activates context → snapshots old thumbprints → Submit-Renewal -RenewAll → rebinds IIS → appends to renewal.log.
↓
3 Posh-ACME Cmdlets ACME protocol layer
Account context
Get-PAServer -List → Set-PAServer (via Resolve-PAServerArg) → Get-PAAccount -List → Set-PAAccount -ID or New-PAAccount -Contact -AcceptTos.
Cert lifecycle
New-PACertificate -Domain … -Install (issue + import) · Submit-Renewal -RenewAll or -Force (renew due orders only).
Queries
Get-PAOrder -List -Refresh (orders on active server) · Get-PACertificate (thumbprint, NotAfter) · Remove-PAOrder (delete order).
↓
4 IIS Integration (Microsoft.Web.Administration) read bindings · rebind HTTPS
Read bindings
Get-IISServerManager → enumerate Sites → Bindings → parse bindingInformation (IP:Port:Host) and CertificateHash. Powers the IIS pickers (Select-IISSitesUI, Select-IISBindingsUI) and the Browse screen.
Re-bind on renewal
Set-IISBindingCertificate: locate the HTTPS binding by BindingInformation, set CertificateHash = new thumbprint, CertificateStore = WebHosting, preserve SslFlags (SNI / central store). mgr.CommitChanges() writes applicationHost.config.
↓
5 Persistent Data Stores state that survives between runs
C:\ProgramData\PoshTUI\config.json
System-wide TUI settings: ACMEServer, ContactEmail, KeyType/KeyLength, ValidationPlugin, CertStore. ACL: Administrators:FullControl, SYSTEM:FullControl, Users:Read. Read by Load-Config, written by Save-Config.
C:\ProgramData\PoshTUI\ACME\ POSHACME_HOME
Shared Posh-ACME data store (set via machine-wide POSHACME_HOME env var). Holds servers/<srv>/, acct/<id>/acct.json, orders/<order>/. Visible to BOTH the admin user and SYSTEM — master for ACME state.
Windows Certificate Store
Cert:\LocalMachine\WebHosting (default). Posh-ACME imports issued certs here via -Install. IIS HTTPS bindings reference these by thumbprint.
applicationHost.config
IIS metabase (C:\Windows\System32\inetsrv\config\applicationHost.config). Stores HTTPS bindings — each carries a certificateHash + certificateStore + sslFlags.
C:\ProgramData\PoshTUI\renewal.log
Append-only structured log written by PoshAcme-Renew.ps1. One line per event: ts [INFO|OK|WARN|ERROR] msg. Viewed via T → l <n>.
Windows Task Scheduler
Registered tasks named PoshTUI-*. Action: pwsh.exe -NoProfile -ExecutionPolicy Bypass -File PoshAcme-Renew.ps1 -ServerName … -AccountID …. Managed via Register-ScheduledTask / Unregister-ScheduledTask.
↓
6 External ACME Server the actual CA endpoint
ACME directory endpoint
Built-in aliases: LE_PROD, LE_STAGE, ZEROSSL_PROD, GOOGLE_PROD, GOOGLE_STAGE, SSLCOM_RSA, SSLCOM_ECC, ACTALIS_PROD — or any custom HTTPS URL such as https://acme.fragt.root.local. Posh-ACME handles ACME protocol (account registration, order placement, challenge validation, cert fetch) over HTTPS.
