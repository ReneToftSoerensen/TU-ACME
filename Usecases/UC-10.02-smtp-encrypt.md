# UC-10.02: SMTP Credential Encryption

## Narrative

As a **security-conscious operator**, I want to **store the SMTP password encrypted**, so that **credentials are not readable in plaintext from the config file**.

## Acceptance Criteria

- [x] SMTP password prompt uses `Read-Host -AsSecureString`
- [x] Password is converted to DPAPI-encrypted string via `ConvertFrom-SecureString` (no key)
- [x] Encrypted password is stored in `config.json` alongside plaintext server/port/username
- [x] On config load, encrypted password is decrypted via `ConvertTo-SecureString`
- [x] Decrypted password is used for SMTP operations
- [x] DPAPI encryption is per-user on this machine (cannot be transferred between machines or accounts)
- [x] A blank password (unauthenticated internal relay) is allowed: an empty `SecureString` is **not** passed to `ConvertFrom-SecureString` (which rejects it), an empty `EncryptedPassword` is stored, and the menu skips the password prompt when no username is entered (issue #15)

## Implementation Notes

- SMTP config stored in config.json with both plaintext and encrypted fields
- Keyless `ConvertFrom-SecureString` DPAPI is scoped to the writing user on this machine
- `Set-TUACMESMTPConfig -Password` is optional; encryption runs only when the `SecureString` is non-empty, so unauthenticated relays store an empty `EncryptedPassword`
- Passwords never logged to Event Log
